## 2. 지금까지 결정된 것

### 목적
카톡 보고를 없앤다. 직원이 ERP에 입력하고 제출(또는 체크) 한 번 → 담당자에게 디스코드/텔레그램 알림 → 대시보드에 실시간 반영.

### 핵심 흐름
배정 → 수행 → **보고 제출** → 검토자 알림 → 승인/반려 → 담당자 알림

### 소통 채널
- **디스코드 기본** (채널·스레드 구조, 사용자 ID 멘션, 웹훅 5분 연동)
- 텔레그램은 모바일 푸시용 보조. 사용자별로 "디스코드 / 텔레그램 / 둘 다" 선택
- 카카오 알림톡은 내부용 부적합 → 제외

### 알림 라우팅 (설계서 4-2)
| 이벤트 | 받는 사람 |
|---|---|
| 업무 배정 | 담당자 |
| 보고 제출 | 배정자(검토자) + 우선순위 높음이면 대표 |
| 승인/반려 | 담당자 |
| Todo 완료 체크 | 상대방 (대표↔팀장) |
| Todo 지남 → 오늘 이동 | 상대방 |
| 새 문의 | 담당 대리 + 대표 |
| 마감 D-1·지연 요약·18:30 대표 리포트 | 2단계에서 cron |

### 기술 스택 (권장, 아직 구현 전)
Next.js + Supabase(Postgres·Auth·**Realtime**·Storage·Edge Functions) + Discord Webhook/Bot. 월 4만 원 이하.
Firebase Studio 워크스페이스라 Firebase로도 가능하나 집계·리포트 때문에 Supabase 1순위.

### 로드맵
1. MVP(1~2주): 로그인·역할, Todo 표, 템플릿 보고, 승인/반려, 디스코드 알림, 실시간, 출퇴근
2. (3~4주): 문의 파이프라인 + 홈페이지 폼 연동, 일일보고, 텔레그램, 마감·지연 자동 알림
3. (5~8주): 디스코드 ✅ 반응·답글 → ERP 반영, 순위 자동 수집, 주간 리포트, PWA

## 3. 프로토타입 (`erp/index.html`) 현재 기능

탭 순서: **할 일 · 대시보드 · 업무 보고 · 문의 · 마케팅 · 설정 · 시스템 설계**

| 탭 | 구현된 것 |
|---|---|
| 할 일 | 노션 Todo 표 그대로. Today/어제/이번 주/지남/전체 보기, 담당자 필터, 완 체크 → 완료 여부 자동(할 일/완료/지남), 이름·설명·날짜 인라인 편집, 새로 만들기·+ 새 페이지, Enter로 다음 행, 열기(상세·담당·삭제), 지남 → 오늘 이동. 체크·배정·이동 시 알림 |
| 대시보드 | KPI 4개(오늘 할 일·검토 대기·지연·이번 주 문의), 검토 대기 목록, 내 할 일(인라인 제출), 실시간 활동, 최근 문의, 공지, 알림 발송 내역 |
| 업무 보고 | 유형별 템플릿(블로그·순위·리뷰·광고·문의·현장·기타) 입력 → 제출 → 검토자 승인/반려 |
| 문의 | 파이프라인(신규→상담 중→현장방문→견적발송→계약→종료), 단계·담당 변경 시 알림 |
| 마케팅 | 키워드 순위표(전일 대비), 광고 지출·문의·문의당 비용, 블로그 발행 목록 |
| 설정 | 디스코드 웹훅 URL, 텔레그램 봇 토큰·chat_id, 사용자별 디스코드 ID·텔레그램 chat_id·채널, 라우팅 규칙 표, 테스트 발송, 데모 초기화 |
| 시스템 설계 | 설계서 요약 |

기술 메모
- 상태는 `localStorage` 키 `cheolgeo-erp-v1`, `state.version===2`. 구조를 바꾸면 version을 올려 재시드.
- 탭 두 개를 열면 `storage` 이벤트로 즉시 동기화 → 실시간 대시보드 시연용.
- 알림은 브라우저에서 직접 `fetch`(디스코드 웹훅 / `api.telegram.org`). **데모 전용**. 실제 서비스는 서버에서 보내고 토큰은 서버에만.
- 상단에서 사용자를 바꿔 대표·팀장·대리 시점을 볼 수 있음(로그인 대체).
- 초기 데이터: 대표·팀장의 실제 Todo 항목(9/21, 9/22)과 예시 업무·문의·키워드. 인물: 이상혁 대표, 김민준 팀장, 박서연 대리, 최지훈 대리 (팀장·대리 이름은 가명).
- 라이트/다크 모두 대응, 휴대폰 폭에서 메뉴가 둘째 줄로 내려옴.

## 4. 아직 안 정해진 것 (대표님 답변 필요)

대화 중 나온 질문 4가지. 답에 따라 대시보드의 축이 바뀝니다.

1. **회사의 정체**: 철거의정석 한 브랜드인가, 여러 업체(디와이·주간보호·파주필라테스·심플치과 등)의 마케팅을 대행하는가? → 대행이면 기본 축을 "사람"이 아니라 "거래처"로 바꿔야 함.
2. **매일 아침 보고 싶은 숫자 3개** (예: 어제 문의 수, 이번 달 광고비, 인천철거 순위).
3. **그 숫자가 지금 어디 있는가** (네이버 광고 관리자, 애드로그, 플레이스, 엑셀, 담당자 머릿속) → 자동 수집 가능 여부.
4. **가장 아팠던 순간 하나** (문의 놓침 / 해놓고 보고 안 됨 / 마감 밀림) → 이슈 층의 첫 규칙.

제안한 대시보드 3층 구조: **성과 층**(거래처별 문의·광고비·문의당 비용·순위) / **실행 층**(Todo, 현재 구현됨) / **이슈 층**(지남 3일↑, 미응답 문의 24h, 순위 급락, 예산 초과를 시스템이 올려줌). 현재는 실행 층만 있음.

## 6. 디스코드·텔레그램 연결 방법 (프로토타입 테스트용)

- 디스코드: 서버 설정 → 연동 → 웹후크 → 새 웹후크 → URL 복사 → ERP 설정 탭에 붙여넣기 → "나에게 테스트 발송"
- 텔레그램: @BotFather `/newbot` → 토큰. 받을 사람이 봇에게 먼저 아무 말이나 보낸 뒤 `https://api.telegram.org/bot<토큰>/getUpdates` 에서 `chat.id` 확인 → 설정 탭 사용자 행에 입력
- 사용자별 디스코드 ID: 디스코드 설정 → 고급 → 개발자 모드 켜기 → 프로필 우클릭 → ID 복사 (멘션에 사용)
